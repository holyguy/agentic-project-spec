# 故障排查

系统化的问题诊断流程，从信息收集到根因定位再到修复验证。

## 步骤

### 1. 收集错误信息

- 获取完整的错误消息和堆栈跟踪
- 确认错误发生的环境（开发/测试/生产）
- 确认错误的复现步骤
- 检查相关日志文件

### 2. 复现问题

- 按照用户描述的步骤尝试复现
- 如果无法复现，收集更多环境信息：
  - 操作系统和版本
  - 浏览器及版本（前端问题）
  - Node.js / Python 版本
  - 依赖版本

### 3. 定位根因

采用**二分法**缩小范围：

1. 确定问题首次出现的时间点
   ```bash
   git bisect start
   git bisect bad HEAD
   git bisect good <已知正常的提交>
   ```
2. 检查最近的相关代码变更
   ```bash
   git log --oneline -20 -- <相关文件路径>
   ```
3. 逐层排查：网络 → API → Service → Repository → 数据库

### 4. 制定修复方案

- 编写失败测试用例复现问题
- 实施最小化修复（避免引入新问题）
- 确保修复不破坏现有功能

### 5. 验证修复

```bash
# 运行完整测试套件
pnpm test
# 或
pytest

# 确认原始问题不再复现
# 确认无回归问题
```

### 6. 记录问题

- 在 `docs/CHANGELOG.md` 中记录修复
- 如果是架构层面的问题，考虑创建 ADR
- 更新 `STATUS.md` 中的已知问题列表

验证清单：
- [ ] 问题根因已明确
- [ ] 修复测试用例已编写
- [ ] 所有现有测试通过
- [ ] 原始问题不再复现
- [ ] 文档已更新
